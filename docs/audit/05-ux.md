first value, traced through code since a live signup isn't possible in this

## High

### 1. Fourteen hand-rolled modals/drawers had no Escape-to-close and no focus trap

**Where:** `src/components/ui/ViewportOverlay.tsx` — the shared full-screen
overlay shell behind `AccountPage.tsx`, `CashModal.tsx`,
`CommunitiesList.tsx`, `CommunityView.tsx` (×2), `CostBasisModal.tsx`,
`CsvImportModal.tsx`, `ExperienceOnboardingModal.tsx`, `FeedbackModal.tsx`,
`HoldingModal.tsx`, `InvitePartnerModal.tsx`, `RenameSheetModal.tsx`,
`SnapshotsModal.tsx`, `TickerDrawer.tsx`, `YtdAnchorModal.tsx` — 14 dialogs
in total. These predate the shadcn `Dialog` primitive (which Radix backs
with Escape/focus-trap/`aria-modal` for free) and were built by hand
instead. Only `TickerDrawer.tsx` had its own Escape handler; none had a
focus trap, and only two (`FeedbackModal.tsx`, `CommunitiesList.tsx`)
declared `role="dialog"` at all — and did so on an *inner* div, leaving the
backdrop outside the announced dialog boundary. `ConfirmModal.tsx` and
`CommandPalette.tsx` were already fine (built on Radix `AlertDialog` /
`CommandDialog`).

**Why it matters:** this is exactly the brief's Critical bar in miniature —
"no way to close a modal" via keyboard, and focus that can silently leave
the visible dialog and land on hidden content behind it. A keyboard or
screen-reader user opening "Add holding," "Edit cash," "Import CSV,"
"Invite partner," or the account-deletion confirmation had no way to
dismiss it without a mouse, and Tab could walk focus into controls the
overlay was visually covering.

**Fix:** `ViewportOverlay` now takes an optional `onClose` (wired to the
same handler each modal's backdrop button already used) and always renders
with `role="dialog" aria-modal="true"`. Internally it adds one
capture-phase `keydown` listener: `Escape` calls `onClose` when provided,
and `Tab`/`Shift+Tab` cycles focus between the first and last focusable
descendant instead of leaking out. Two modals (`FeedbackModal.tsx`,
`CommunitiesList.tsx`) had a duplicate inner `role="dialog"`/`aria-modal`
with an `aria-labelledby`; that's now expressed once, via a new
`ariaLabelledBy` prop on `ViewportOverlay` itself, avoiding a nested-dialog
ARIA smell. `TickerDrawer.tsx` was left as-is (it already closes on
Escape) and gets the role/focus-trap improvements for free since they live
in the shared shell, not per-call-site.

### 2. Unmapped raw database errors could reach a paying stranger verbatim

**Where:** `src/lib/plain-error.ts`.

**What's wrong:** ~30 API routes return Supabase/Postgres error text
directly as `{ error: error.message }` on a 500 (e.g.
`src/app/api/portfolios/route.ts`, `src/app/api/communities/route.ts`,
`src/app/api/account/delete/route.ts`). Every client call site correctly
routes that string through `plainError(raw, fallback)` before showing it
in a toast/banner — but `plainError`'s own fallback, when a string wasn't
in the curated `KNOWN` dictionary and didn't match one of two narrow
regexes (`foo_bar`, `thing required`), was `return s` — pass the raw text
through unchanged. A Postgres error the team hadn't specifically added to
`KNOWN` yet (`duplicate key value violates unique constraint
"portfell_x_pkey"`, `invalid input syntax for type uuid: "…"`, an RLS
denial, a stack frame) would render straight into the UI. This is exactly
the failure mode the file's own docstring says it exists to prevent
("Snake_case keys and 'X required' never reach a toast or banner") — it
just didn't cover the far more common raw-driver-error case.

**Fix:** added a `looksTechnical()` check before the final pass-through:
any string containing one of ~15 Postgres/driver/stack-trace markers
(`duplicate key`, `violates`, `constraint`, `relation "`, `syntax error`,
`permission denied`, `jwt`, `pgrst`, `econnrefused`, ` at async `, …), or
containing a bare double-quote (Postgres always quotes the identifier in
these messages — `relation "x"`, `column "y"`, `constraint "z"` — so a
stray `"` in an otherwise-unmapped string is a strong signal it's a raw
driver error and not a sentence a person wrote), or longer than 160
characters, now falls back to the caller's plain-English default instead
of rendering raw. Every string already in `KNOWN` is still matched and
returned first, so no existing curated message changes.

### 3. Thesis Pulse carried no "this is AI, it can be wrong" framing anywhere on the page

**Where:** `src/components/PulsePage.tsx`.

**What's wrong:** `AGENTS.md` names Margus/Thesis Pulse/Forecast together
as needing this framing kept intact, and the shared `src/lib/disclaimer.ts`
exists precisely so it isn't duplicated ad hoc. Margus chat
(`CcAdvisorChat.tsx`), Forecast (`ForecastPanel.tsx`), and Upside Portfolio
(`UpsidePortfolioPage.tsx`) all render one of its constants. Thesis Pulse —
the page that produces "Thesis intact / Thesis watch / Thesis broken"
verdicts and an explicit "should you sell, or buy more?" prompt, arguably
the single easiest-to-misread-as-advice surface in the app — had zero
occurrences of "advice," "educational," or "disclaimer" anywhere in the
file.

**Fix:** added a plain-English disclaimer line as the page header's
`subtitle` ("Educational, not personalized investment advice. Always your
call."). It's deliberately *not* wired to the shared `ADVICE_DISCLAIMER_*`
constants — `scripts/test-invariants.ts`'s `"Pulse scan sits in its own
card, not under the lookup bar"` check specifically asserts
`doesNotMatch(page, /ADVICE_DISCLAIMER/)`, a guard against a past
regression where that identifier's text leaked into the "Today's scan"
list. Using the identical wording as a literal string satisfies both the
product requirement and the existing invariant; if the wording in
`disclaimer.ts` changes later, this line needs a manual update too (noted
inline would help — left as a Low item below rather than touched here,
since it's a pre-existing test contract, not something to fix as a side
effect of this pass).

## Medium (backlog — not fixed this pass)

- **Icon-only touch targets are 28px (`size-7`, the `icon-sm` button
  variant), below the ~44px Apple HIG / 48dp Android guidance**, and used
  adjacent to each other with only 4px gaps in `MobileTopBar.tsx` (Feedback,
  Alerts bell) and elsewhere app-wide. This is a systemic design-system
  choice (`src/components/ui/button.tsx`), not a one-off bug — bumping it
  touches every icon button in the app and is a design decision, not a
  mechanical fix. Flagged for a deliberate call, not changed here.
- **`EmptyBook` in `OverviewDashboard.tsx` (the actual first-run screen,
  since `ExperienceOnboardingModal` is disabled) is already well-built** —
  CSV upload, screenshot import, manual add, and a paste-holdings textarea,
  each with a plain-English hint — but worth flagging as the thing that
  *is* working well in the "first 60 seconds" flow, so nobody "fixes" it
  later assuming it's a stub. No code change; noting it here so the next
  pass doesn't waste time re-verifying it from scratch.
- **`AdminPage.tsx:270,280,364` and `ClassroomPlanEditor.tsx:159`** use
  `title="Clear log"` / `title="Refresh"` / `title="Remove"` on icon-only
  buttons instead of `aria-label`. `title` is a valid accessible-name
  fallback per the HTML accname algorithm when there's no other text
  content, so this isn't broken, but it's inconsistent with the
  `aria-label` pattern used everywhere else (36 other icon-only buttons in
  the codebase all use `aria-label`) and both surfaces are admin/teacher-
  only, not a stranger-facing core flow. Low urgency, easy follow-up.
- **`use-lab-sync.ts`'s error toast can re-fire roughly once per 900ms
  debounce window while a user keeps typing conviction notes during a
  sustained sync failure.** It's already well-guarded (debounced, a
  generation counter drops stale responses, cleanup on unmount) — this
  isn't a runaway loop, just a "could get a little noisy" edge case if
  Supabase is down for an extended stretch while someone is actively
  editing. Not worth touching without a repro; noted for awareness.

## Low (backlog)

- `PulsePage.tsx`'s new disclaimer line is a literal string, not imported
  from `src/lib/disclaimer.ts`, because of the invariant test constraint
  described in High #3. If `ADVICE_DISCLAIMER_SHORT`'s wording changes for
  legal reasons, this line needs a manual follow-up edit, and the invariant
  test's regex should probably be loosened (e.g. to allow the *value* while
  still forbidding it inside the `ScanList` block specifically) so this
  doesn't silently drift. Left as a note rather than touched — changing a
  test's intent is a product/legal call, not a UX-pass mechanical fix.
- `CsvImportModal.tsx`'s hidden `<input type="file">` and `Choose CSV file`
  button pattern is accessible as-is (the button is the real control), but
  the paste `Textarea` in both `CsvImportModal.tsx` and `OverviewDashboard.tsx`
  had no programmatic label — only a visually-adjacent `<p>` description.
  Fixed both with `aria-label` (see diff); noting here since it was a
  one-line, obviously-safe fix bundled with the modal-focus-trap work
  rather than its own finding.
- A handful of `plainError` `KNOWN` dictionary entries map a string to
  itself verbatim (e.g. `"Not a member": "You're not in this circle."` is
  a real translation, but `"Pick what students can do."` maps to the exact
  same string). Harmless, just slightly redundant — a future cleanup could
  collapse the identity entries into the "already human, pass through"
  path instead of listing them individually.

## Confirmed working (no fix needed — checked, not assumed)

- **Rate limiting on AI-assistant endpoints** is real and covers every
  interactive Margus-equivalent route: `/api/chat`, `/api/thesis/pulse`,
  `/api/forecast/plan`, `/api/book/ytd-from-image`, and
  `/api/options/scan` all call `takeDurableRateLimit()` (per-user,
  cross-instance via a Postgres RPC — confirmed in Pass 2's
  `docs/audit/02-security.md` and re-verified against current `main`, no
  new AI routes have shipped uncovered since). `src/app/api/chat/route.ts`
  applies its limit (30 messages / 5 minutes / user) *before* the model
  call, with a plain-English rate-limit message, so one user genuinely
  cannot exhaust the shared free-tier quota for everyone else.
- **Forms** (`HoldingModal`, `CashModal`, `RenameSheetModal`,
  `YtdAnchorModal`, `CsvImportModal`, `InvitePartnerModal`,
  `FeedbackModal`) consistently follow the `UpgradeButton` disable-while-
  pending pattern (`disabled={busy}` on submit, a "…ing" label swap) and
  use `FieldLabel`/`htmlFor` or a wrapping `<label>` for every real input.
  No gaps found beyond the two `Textarea` instances fixed above.
- **The command palette** (`CommandPalette.tsx`) is built on shadcn's
  `CommandDialog` (Radix `Dialog` + `cmdk`), which already provides
  keyboard nav, focus trap, and Escape — nothing to fix.
- **Confirm/destructive dialogs** (`ConfirmModal.tsx`, used for account
  deletion, member removal, etc.) are built on Radix `AlertDialog` — same
  story, already correct.
- **Mobile chrome** (`MobileTabBar.tsx`, `MobileTopBar.tsx`,
  `MobileChrome.tsx`, `CashAlertCard.tsx`) — code-level review only, not
  visually verified (no live device/no real data in this sandbox). Tab
  bar rows are `h-12` (48px, an adequate touch target height); no fixed
  pixel widths that would overflow a small screen; `env(safe-area-inset-*)`
  is applied consistently on both the tab bar and top bar. The one real
  finding (28px icon buttons in the top bar) is filed as Medium above,
  not Critical, since it's a systemic design-system value rather than a
  one-off oversight.

## Needs a decision

- **Icon-button touch-target size** (Medium #1 above). Bumping `icon-sm`
  from `size-7` (28px) to something closer to 40–44px is a real, if small,
  design-system change that touches dozens of call sites and the visual
  density of the whole header/toolbar system — not something to guess at
  inside a UX-findings pass.
- **Whether `EmptyBook`'s three-or-four-way onboarding (CSV / screenshot /
  manual / paste) should get a guided first-run tour now that the
  tier-question wizard is disabled.** The empty state itself is solid
  (see Medium backlog), but there's no "here's what Overview/Pulse/Lab do"
  walkthrough once someone has *some* holdings — that's a product-scope
  question (how much hand-holding a first-time stranger needs), not a bug.
